# MCP 长期记忆系统 PRD

## 目标

让 AI 客户端能够跨会话写入、检索和删除用户记忆，并在后续对话中按语义相关性召回，使系统能够持续理解用户。

## 技术栈

- MCP：由 Python 服务端暴露记忆工具。
- Python：MCP Server、REST API、嵌入生成和业务逻辑。
- MySQL：用户、会话、记忆正文、标签、状态和时间等结构化数据。
- Milvus：记忆向量和语义相似度检索。
- Vue3：记忆列表、筛选、编辑、删除和搜索界面。

## 核心功能

### 写入记忆

- 输入：文本、用户 ID、可选会话 ID、可选标签。
- 处理：生成统一记忆 ID；MySQL 记录正文与元数据；生成嵌入并写入 Milvus；记录同步状态。

### 检索记忆

- 输入：查询文本、用户 ID、topK，以及可选会话、标签和时间范围。
- 处理：生成查询向量；Milvus 按用户和可选条件召回；按 ID 联查 MySQL；返回排序后的记忆。

### 记忆管理

- 列表展示和分页。
- 按用户、标签和时间筛选。
- 编辑正文或标签；正文变化后重新生成向量。
- 删除记忆，同时清理 Milvus 向量。

### MCP 工具

- `write_memory`
- `search_memory`
- `delete_memory`

## 验收标准

- 三个必需 MCP 工具可被 MCP 客户端发现和调用。
- 写入后 MySQL 与 Milvus 均能查询到对应记录。
- 搜索只能返回指定用户的活动记忆。
- 删除后搜索和列表均不再返回该记忆。
- Vue3 页面可完成列表、筛选、搜索、编辑和删除。
- 后端核心业务具备自动化测试。

## 边界与约束

- MySQL 是记忆正文和生命周期状态的事实源；Milvus 是可重建的向量索引。
- 所有检索必须包含用户 ID，防止跨用户泄露。
- 本地开发默认连接 `127.0.0.1:3308` 的 MySQL 和 `127.0.0.1:19530` 的 Milvus。
- 嵌入实现可配置；测试环境使用确定性假实现，实际运行使用本地语义模型。
